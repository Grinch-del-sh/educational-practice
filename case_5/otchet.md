# Кейс-задача № 5: Аналитический обзор

**Выбранная задача для анализа:** Кейс-задача № 3 (Веб-приложение на фреймфорке Django для ввода и хранения имён).

## 1. Функциональность
**Оценка:** Высокая.
**Обоснование:** Программа полностью выполняет поставленные задачи. Веб-приложение корректно обрабатывает GET-запросы (вывод формы на главной странице) и POST-запросы (отправка имени). Данные успешно сохраняются в базу данных SQLite через Django ORM. При успешной отправке пользователь видит персонализированное приветствие. Если поле ввода пустое, срабатывает встроенная валидация формы, и пользователь получает сообщение об ошибке.

## 2. Производительность
**Оценка:** Высокая для текущего масштаба.
**Обоснование:** Приложение работает на локальном сервере разработки. База данных SQLite и ORM Django обеспечивает мгновенную запись и чтение данных (отклик менее 100 мс). Для текущего объёма данных (единичные записи) производительность оптимальна. При росте нагрузки потребуется переход на более мощные СУБД (например, PostgreSQL) и кэширование, но для учебной задачи текущая скорость избыточна.

## 3. Удобство использования (Юзабилити)
**Оценка:** Высокое.
**Обоснование:** Интерфейс минималистичен и понятен любому пользователю: одно поле ввода и одна кнопка «Отправить». Благодаря подключённому CSS, элементы отцентрованы, имеют приятный внешний вид (тени, скругления, адаптивные шрифты). Понятные сообщения об ошибках (например, если поле оставлено пустым) предотвращают фрустрацию пользователя.

## Безопасность
**Оценка:** Базовая, но надёжная.
**Обоснование:** В приложении реализована защита от атак **CSRF** (Cross-Site Request Forgery) с помощью встроенного тега `{% csrf_token %}`. Django автоматически проверяет этот токен при POST-запросах, предотвращая межсайтовую подделку запросов. ORM Django автоматически экранирует SQL-запросы, что защищает от SQL-инъекций. Валидация данных на стороне сервера продотвращает запись пустых или некорректных данных.

## 5. Масштабируемость
**Оценка:** Высокая (благодаря архитектуре Django).
**Обоснование:** Приложение построено по паттерну MVT (Model-View-Template). Это позволяет легко расширять функционал: можно добавить новые модели (например, для хранения email или возраста), создать новые представления и страницы, не переписывая существующий код. Легко интегрируется с другими библиотеками и подключается к внешним API.

## 6. Сопровождаемость
**Оценка:** Высокая.
**Обоснование:** Код структурирован согласно официальным стандартам Django (разделение на приложения, модели, формы, представления). Присутствуют комментарии, объясняющие логику работы. Чёткое разделение слоёв (логика в `views.py`, структура в `models.py`, валидация в `forms.py`) упрощает поддержку и обновление кода другими разработчиками.

## 7. Переносимость
**Оценка:** Высокая.
**Обоснование:** Проект написан на Python и Django, которые являются кроссплатформенными. Приложение будет одинаково работать на Windows, Linux и macOS. Для запуска требуются только установленный Python, зависимости из `requirements.txt` (Django) и сам исходный код. База данных SQLite не требует установки отдельного сервера.

## 8. Качество кода
**Оценка:** Высокое.
**Обоснование:** Используются стандартные практики проектирования Django. Код читаем, логически разделён. Используются классы форм (`ModelForm`) для автоматической генерации полей и валидации, что снижает вероятность ошибок. Отсутствуют "магические числа" и жёстко зашиты пути.

## 9. Тестирование
**Оценка:** Базовое (ручное).
**Обоснование:** В текущей реализации проведено ручное тестирование (проверка ввода пустых строк, корректных имён, проверка работы CSRF-токена). Для полного соответствия стандартам необходимо написать автоматические Unit-тесты (в файле `tests.py`), которые будут проверять модели и представления при каждом запуске сборки.

## Предложения по решению выявленных проблем

На основе проведённого анализа можно выделить одно слабое место: **отсутствие автоматизированного тестирования** и **использование SQLite для потенциально растущей базы данных**.

**Способы решения:**
1. **Внедрение автотестов:** Написать тесты в файле `tests.py` с использованием встроенного модуля `unittest` или `pytest`. Тесты должны проверять: создание записи в БД при валидной форме, возврат ошибки при пустом поле, доступность главной страницы (код 200).
2. **Переход на PostqreSQL:** Поскольку SQLite блокирует всю базу данных при записи, для масштабирования (если приложением будут пользоваться одновременно сотни людей) рекомендуется настроить подключение к PostgreSQL в файле `settings.py`. Это повысит надёжность и скорость работы под нагрузкой.
3. **Добавление Docker:** Для упрощения развёртывания (переносимости) можно упаковать проект в Docker-контейнер, что позволит запускать его одной командой на любом сервере, независимо от настроек операционной системы.
